# /prompt 提示词生成器

## Purpose
很多人不是不会用 AI，是不知道一条好提示词要交代哪些东西。本 skill 把《如何写好提示词：小白版》的万能公式（任务 + 背景 + 要求 + 例子）变成一段引导对话：我来发问，用户只需回答或跳过，最后我把答案拼成一份成型的提示词。

## Trigger
- **仅手动触发**：用户消息是 `/prompt`，或明确说要用 /prompt 生成提示词时启动。
- 机器层面的禁自动触发靠元数据，不靠正文自觉：Claude Code 版靠 frontmatter 的 `disable-model-invocation: true`；Codex 版靠 `agents/openai.yaml` 里的 `allow_implicit_invocation: false`。移植到其他运行时先落这两个开关，再保留本节文字。
- 其他情况下不自动启动，哪怕用户正在抱怨提示词写不好——可以提醒他有这个 skill，但不要直接开始提问。引用、转述里提到 `/prompt` 也不算触发。

## Workflow
### 第 0 步：预解析（先扫已有输入，只问缺口）
启动时先把用户已经给出的全部内容（`/prompt` 后跟的文字、粘贴的 brief、前面几轮对话里已说清的信息）按下面 8 项逐项扫一遍：

- 已经说清的项直接记下，不再问。
- 只问还缺的项。用户开头给的是长 brief 时，通常只需补问 2–3 项。
- 任务（第 1 项）已在输入里出现时同样跳过，不重复问。

扫完后用一句话告诉用户：哪几项已从他的输入里记下、接下来只问哪几项。

### 提问环节（一次只问一题，按顺序问缺项）
每道题都要附一个可点的「无，跳过这一项」选项（用选项控件给出），用户点它或直接回复"无 / 跳过 / 没有"都算跳过，进入下一题。用户自由作答时，原样记下要点，不要替他改写或脑补。

1. **任务**（必问，不能跳）：你想让 AI 做什么？一句话就行，比如"写一封道歉邮件""把这篇文章总结成要点"。
2. **背景**：这件事的来龙去脉——为什么做、给谁看、有什么前情？（例：发货晚了 3 天、对方是老客户）
3. **材料**：有没有要 AI 处理的现成材料（文章、数据、聊天记录）？有就贴给我，没有就跳过。
4. **角色**：想让 AI 以什么身份来做？（例：资深财务、小学老师、健身教练）没有偏好就跳过，用默认身份。
5. **格式与长度**：要多长、长什么样？（例：300 字以内、列 5 条要点、输出表格）说不准就跳过，我按任务给个合理默认并在成稿里标明。
6. **语气**：正式 / 轻松 / 幽默 / 其他说法，没有就跳过。
7. **禁忌**：有什么绝对不要出现的？（例：不要专业术语、不要编造数据、不要超过一页）没有就跳过。
8. **例子**：有没有一份你满意的样例可以照着学？贴一段就行，没有就跳过。
9. **验收标准**（只对分析类和 Agent 执行类问，写作类不问）：做到什么样算合格？（例：结论要给出处、方案要能直接开工、构建要跑通）没有就跳过，用该类模板的默认验收。

用户中途说"够了 / 直接生成"→ 立即结束提问，用已有答案成稿。说"取消"→ 终止，不成稿。

### 定型环节（选模板）
根据任务选一套模板，成稿前读对应的文件，模板和填法都在里面：

- **写作类**（写邮件、文案、总结、翻译）→ `references/writing.md`
- **分析类**（解读、对比、调研、给建议）→ `references/analysis.md`
- **Agent 执行类**（做项目、写代码、跑多步任务）→ `references/agent-task.md`

拿不准时按任务的主要产出定：产出是一篇文字就是写作类，产出是判断和结论就是分析类，产出是做完的一件事就是 Agent 执行类。

### 成稿环节
按所选模板拼装，跳过或没问的部分整段省略（不要留空标题、不要写"无"）：

- 任务句用动词开头，写具体，不用形容词堆砌。
- 用户给的要求能量化就量化（"300 字以内"优于"简短一点"）；他没给量的不替他编数字。
- 材料用模板里的分隔标记包住，和指令分开，不要和背景混成一段。
- 例子前写清学什么：学结构和语气，不抄内容。
- 不再无条件加「先一步步分析，再给结论」。分析类模板已把分析维度写进要求；要模型展开思路时，给具体维度（先比什么、再看什么风险），不给口号句。
- 角色、语气等答案如果和任务明显冲突（如给小学生讲却要"学术语气"），成稿前提醒一句，让用户改，不自作主张替换。

### 示例（一组完整输入 → 成稿，照此密度和结构）
用户答完后的记录：
- 任务：给老客户写一封发货延迟的道歉邮件
- 背景：晚发 3 天，对方是合作两年的老客户
- 角色 / 语气 / 禁忌：客服主管 / 诚恳正式 / 不要推责、不要送优惠券
- 格式：200 字以内
- 材料、例子、验收：跳过（写作类不问验收）

成稿（写作类模板）：
```
你是一位客服主管。
任务：给一位老客户写一封发货延迟的道歉邮件。
背景：订单晚发了 3 天，对方是合作两年的老客户。
要求：
1. 200 字以内，诚恳、正式。
2. 说明延迟原因和新的送达时间，不要推卸责任。
3. 不要提优惠券或补偿方案。
交付前对照上面要求逐项自查一遍再给我。
```

### 交付环节
1. 把成稿放在一个代码块里，方便整段复制。
2. 代码块后用一句话说明：用了哪套模板、哪些部分来自他的回答、哪些是我按默认补的（只提真正补了的）。
3. 问一句要不要调整（换语气、加/减一项），或直接帮他拿这份提示词跑一遍——他选跑，就在当前对话里以这份提示词为指令执行任务。

## Operating Rules
1. 一次只问一题，等回答了再问下一题，不要把问题一股脑列出来。预解析的汇总不算提问，可以一次说清。
2. 每题必须给"无/跳过"的出口，不要在任何一题上卡住用户。
3. 不替用户编造答案：他跳过的就是没有，成稿宁可短而实，不要为了好看往里填他没说过的内容。模板自带的默认条款（验收、不确定时怎么办、交付前自查）属于模板结构，不算替他编，但交付时要标明是默认补的。
4. 提问语气简短口语化，每题可附一个小例子帮他理解在问什么，但例子不要长。
5. 成稿后不自动上传文档中心、不自动执行任务，除非用户明确要求。
