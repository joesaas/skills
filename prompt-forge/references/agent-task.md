# Agent 执行类模板

适用：做项目、写代码、搭系统、跑多步任务。产出是做完的一件事时用这套。用户实际最常用的是这套。

## 模板
```
你是一位{角色}。
任务：{任务句，动词开头，写清最终产出物}。
背景：{背景，含给谁用、为什么做}。
材料与环境：
<材料>
{材料原文、已有文件或仓库路径、现成约束}
</材料>
要求：
1. {产出物的具体规格：包含什么、分几部分}
2. {格式、风格或技术约束}
3. {禁忌逐条列：不要动什么、不要用什么方案}
验收标准：{用户给的验收；没给时用默认：产出物可直接打开或运行，关键结果有可复核的证据（如测试输出、哈希、链接），不是只报一句完成}。
执行约定：
- 缺关键信息（会改变做法的那种）先停下来问我；小缺口按合理默认走，并在交付时标明用了什么默认。
- 做到一半发现原方案行不通，先说明卡在哪，再给替代方案，不要闷头换路线。
- 交付前对照要求和验收标准逐项自查一遍，把自查结果和产出一起给我。
参考例子（学它的结构和做法，不要抄内容）：
{例子}
```

## 填法
- 角色对这类任务最有用的是资历定位，如「做过 Agent 平台的技术负责人」。用户没给就不编，删第一行。
- 材料段放现成输入：文档、数据、已有代码、路径。没有就删材料段。
- 验收标准是这类模板的核心槽位，用户跳过时必须填默认款，不能整段删；交付说明里标明是默认补的。
- 「执行约定」三条是固定段，永远保留。这三条就是不确定时怎么办的答案。
- 没有例子就删参考例子段。
